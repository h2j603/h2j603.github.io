* + *

뭐냐면

A + B는 A 바로 뒤에 붙은 B. 둘 다 *로 두면 앞에 형제가 있는 요소 전부가 걸린다. 첫째만 빠진다.

.stack > * + * {
  margin-top: 1em;
}
  +----------+
  | A        |  ← 첫째. 안 걸림
  |//////////|  ← 여기만 margin
  | B        |
  |//////////|
  | C        |
  +----------+  ← 끝에 남는 여백 없음

모양이 멍한 부엉이 눈 같다고 Heydon Pickering이 lobotomized owl이라고 불렀다(2014). 원래 글에서는 .stack > 없이 * + * 한 줄을 페이지 전체에 걸었다. 요소마다 여백을 주지 말고 “흐름 안의 모든 것은 앞의 것과 1.5em 떨어진다”는 공리 하나로 시작하자는 얘기였다.

margin-bottom이랑 뭐가 다른가

> * { margin-bottom }

A
B
C

> * + * { margin-top }

A
B
C

점선이 부모 끝. margin-bottom 쪽은 C 밑에 여백이 남아서 밖으로 샌다. 그래서 보통 :last-child { margin-bottom: 0 }을 또 쓰게 되는데, 부엉이는 처음부터 그럴 일이 없다.

> 를 붙이는 이유

원래대로 * + *만 쓰면 후손 전부가 걸린다. 안쪽 목록, 버튼 속 아이콘까지 다 벌어진다. 지금은 대부분 >로 바로 아래 자식만 잡고, 간격을 줄 곳에 .stack을 직접 단다.

>가 없는 쪽은 B 안의 b1, b2 사이까지 벌어졌다.

간격을 관계로 적는다

제일 마음에 든 부분. “제목은 아래 24px”이 아니라 “제목 다음은 붙이고, 제목 앞은 띄운다”로 적는다. 여백이 요소의 성질이 아니라 둘 사이의 성질이 된다. 클래스를 안 달아도 글 순서만으로 리듬이 생긴다.

.rhythm > * + *          { --gap: .3em }
.rhythm > * + h4         { --gap: 1.6em }
.rhythm > h4 + *         { --gap: 0 }
.rhythm > * + blockquote { --gap: 1em }

화요일

그리드 다시.

*의 명시도가 0이라서 .rhythm > * + *는 클래스 하나 무게밖에 안 된다. 그래서 아래 줄들이 위의 기본값을 쉽게 이긴다. 기본은 가볍게, 예외는 구체적으로.

값은 변수로

처음엔 규칙마다 margin-top을 직접 썼다. 그러다 간격 값을 --space 하나로 빼니까 스택마다 값만 바꿔 끼우면 됐다.

.stack > * + * { margin-top: var(--space, 1em) }
.box   { --space: 12px }
.post  { --space: 1.5em }

문제는 변수가 상속된다는 것. 안쪽 스택이 바깥 값을 물려받아 엉뚱하게 벌어진다. 그래서 이 페이지는 관계마다 정하는 값을 --gap으로 따로 두고, @property로 상속을 껐다.

이 페이지 만들다 걸린 것

① --gap의 상속을 껐더니 빗금 높이가 0이 됐다. 빗금은 ::before로 그리는데 ::before도 자식이라 못 받은 거였다. 상속되는 --band에 한 번 옮겨 담아서 해결.

② 섹션 사이가 다닥다닥 붙었다. 섹션이 자기 안쪽용으로 정한 --space가 섹션 자신의 위 여백에도 쓰였다. 바깥 간격은 main > * + *에서 따로 주는 걸로.

③ 사파리에서 <hr>에는 ::before가 안 그려졌다. 그래서 구분선은 그냥 div.

정리

- 간격은 요소가 아니라 관계에 준다.

- >를 붙여서 바로 아래 자식만.

- 기본은 * + *로 가볍게, 예외는 h4 + *처럼 구체적으로.

- flex·grid 안이거나 항목이 숨었다 나타나면 gap.

- 글처럼 흐르는 곳, 관계마다 간격이 달라야 하는 곳이 부엉이 자리.
