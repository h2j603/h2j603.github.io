overflow: auto

넘친 내용을 잘라 두고 안에서 굴릴 수 있게 된 상자를 스크롤 컨테이너라고 한다. overflow가 auto, scroll, hidden 중 하나면 그렇게 된다. 페이지 전체도 하나의 스크롤 컨테이너다.

sticky, scroll-snap, scroll-margin, overscroll-behavior, 스크롤 애니메이션까지 전부 가장 가까운 스크롤 컨테이너를 기준으로 움직인다. 스크롤 CSS가 안 먹을 때는 대부분 기준이 다른 상자로 잡힌 경우다.

  +----------+
  |          |  ← 보이는 영역
  |          |
  +----------+
  :          :  ← 잘린 내용.
  :          :    굴려야 보임
  +..........+

hidden도 스크롤 컨테이너다

overflow: hidden은 스크롤바만 없앨 뿐 스크롤 컨테이너는 그대로 만든다. 스크립트로 굴릴 수도 있다. 진짜로 자르기만 하는 값은 overflow: clip이다.

그래서 hidden 안에 넣은 sticky는 바깥 스크롤을 못 본다. 가장 가까운 컨테이너가 굴러가지 않는 hidden 상자로 잡혀서다.

.wrap { overflow: hidden }

두 상자를 굴려 본다. hidden 쪽 검은 줄은 같이 올라가 버리고, clip 쪽은 위에 붙는다. 아래 토글을 켜면 hidden 쪽에만 안쪽 상자가 하나 더 칠해진다.

한쪽만 줘도 양쪽이 바뀐다

overflow-x: hidden만 쓰고 y는 그대로 두면 y가 visible로 남지 않고 auto로 바뀐다. 한 축이 컨테이너가 되면 다른 축도 따라간다. 가로 넘침만 막으려고 쓴 한 줄이 sticky를 깨는 흔한 경로다. 이럴 때도 clip을 쓰면 된다.

/* y → auto */
.page { overflow-x: hidden }

/* y는 visible 그대로 */
.page { overflow-x: clip }

스크롤바 자리 미리 잡기

윈도우처럼 스크롤바가 폭을 차지하는 환경에서는, 내용이 길어져 스크롤바가 생기는 순간 본문 폭이 줄면서 화면이 옆으로 움찔한다. scrollbar-gutter: stable은 스크롤바가 없을 때도 그 폭을 비워 둔다. 맥·아이폰처럼 스크롤바가 내용 위에 떠 있는 환경에서는 아무 효과가 없다.

html {
  scrollbar-gutter: stable;
}

sticky

position: sticky는 top 같은 기준값이 있어야 붙는다. 그리고 부모 상자 안에서만 붙는다. 부모가 화면을 벗어나면 같이 밀려 나간다.

.group h4 {
  position: sticky;
  top: 0;
}

붙었는지 아는 sticky

sticky가 지금 붙어 있는지는 원래 CSS로 알 수 없었다. 붙을 때 그림자를 달려면 스크립트로 위치를 지켜봐야 했다. container-type: scroll-state를 주면 붙은 상태를 컨테이너 쿼리로 물을 수 있다. 크롬 133부터 되고, 사파리·파이어폭스는 아직이다(2026년 10월).

h4 {
  position: sticky;
  top: 0;
  container-type: scroll-state;
}
@container scroll-state(stuck: top) {
  h4 span { background: yellow }
}

scroll-snap

굴리다 멈추면 정해 둔 자리에 딱 맞춰 선다. 컨테이너에 방향을, 자식에 맞출 위치를 준다.

.row {
  scroll-snap-type: x mandatory;
  scroll-padding: 8px;
}
.row > * {
  scroll-snap-align: start;
}

mandatory는 반드시 맞춘다. proximity는 맞춤 자리 근처에서 멈췄을 때만 맞춘다. 카드가 화면보다 길면 mandatory는 카드 중간을 못 보게 막을 수 있어서, 그때는 proximity를 쓴다.

scroll-padding은 컨테이너 쪽 여백, scroll-margin은 자식 쪽 여백이다. 둘 다 스냅 자리를 옮긴다.

버튼과 점까지 CSS로

스냅 줄에 이전·다음 버튼과 위치 점을 붙이는 일도 원래 스크립트 몫이었다. ::scroll-button()과 ::scroll-marker를 쓰면 브라우저가 진짜 버튼과 링크를 만들어 준다. 키보드로 움직이고 화면 낭독기도 읽는다. 크롬 135부터 되고, 사파리·파이어폭스는 아직이다(2026년 10월).

.row {
  scroll-marker-group: after;
}
.row::scroll-button(left) {
  content: "←" / "이전";
}
.row::scroll-button(right) {
  content: "→" / "다음";
}
.row > *::scroll-marker {
  content: " ";
}
.row > *::scroll-marker:target-current {
  background: black;
}

scroll-margin

#제목 링크로 뛰면 대상이 화면 맨 위에 붙는다. 위에 고정 머리글이 있으면 그 밑에 깔린다. 대상에 scroll-margin-top을 주면 그만큼 덜 올라간다.

h2 {
  scroll-margin-top: 4rem;
}

페이지 전체에 한 번에 걸고 싶으면 컨테이너 쪽인 html에 scroll-padding-top을 준다. 스냅과 같은 짝이다.

안쪽 숫자 상자를 6까지 내리고 계속 민다. 기본 쪽은 바깥이 따라 내려가고, contain 쪽은 그 자리에 선다.

animation-timeline

애니메이션의 시간을 초가 아니라 스크롤 위치로 바꾼다. 맨 위의 검은 줄이 이 페이지를 굴린 만큼 길어진다. 스크립트는 없다.

.bar {
  animation: grow linear both;
  animation-timeline: scroll(root);
}
@keyframes grow {
  from { transform: scaleX(0) }
  to   { transform: scaleX(1) }
}

scroll(root)는 페이지 전체, scroll(nearest)는 가장 가까운 스크롤 컨테이너를 기준으로 삼는다. 여기서도 기준은 컨테이너다. 지원하지 않는 브라우저에서는 줄이 안 보이게 @supports로 감쌌다.

view(): 들어오는 만큼

scroll()이 컨테이너를 얼마나 굴렸나를 본다면, view()는 요소 하나가 보이는 영역을 얼마나 지나갔나를 본다. animation-range로 그중 어느 구간에 애니메이션을 걸지 고른다. entry는 요소가 아래 끝에 걸치기 시작해서 다 들어올 때까지다.

.item {
  animation: reveal linear both;
  animation-timeline: view();
  animation-range: entry 0% entry 100%;
}

스크롤로 움직이는 화면은 멀미를 부를 수 있다. 실제로 쓸 때는 prefers-reduced-motion로 끌 수 있게 한다.

정리

- 스크롤 CSS는 전부 가장 가까운 스크롤 컨테이너 기준.

- hidden도 컨테이너를 만든다. 자르기만 할 때는 clip.

- sticky가 안 붙으면 조상 중에 overflow가 걸린 상자부터 찾는다.

- 컨테이너 쪽은 scroll-padding, 자식 쪽은 scroll-margin.

- 안쪽 스크롤이 밖으로 새면 overscroll-behavior: contain.

- 스크롤바 생길 때 화면이 움찔하면 scrollbar-gutter: stable.

- 굴린 양은 scroll(), 요소가 지나간 정도는 view().

- 붙은 상태·캐러셀 버튼은 이제 CSS로도 된다. 아직 크롬만.
