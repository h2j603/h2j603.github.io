2026 홍익대학교 시각디자인과 졸업전시 티저 웹(2026.hongiksidi.com)을 작업하며 반응형을 맞춘 순서를 정리했다. 데스크톱에서 시작해 폰을 만들고, 그 사이 화면들을 채운 뒤, 다시 짜며 갈래를 줄였다. 각 단계의 화면은 지금 공개된 티저를 그 크기의 창에 띄운 것이다.

데스크톱

넓은 화면부터 만들었다. 피그마에서 데스크톱 시안을 그리고 HTML로 옮겼다.

화면은 세로 칸(컬럼)으로 나눠 배치했다. 화면이 좁아지면 칸 수만 줄어들게 기준 두 개를 미리 잡아 뒀다. 이때 미디어쿼리는 칸 수를 바꾸는 두 줄이 전부였다.

@media (max-width: 64rem) { 8칸 }
@media (max-width: 40rem) { 4칸 }

폰

그다음 폰 화면을 따로 짰다. 데스크톱을 그대로 줄이는 대신, 폰 블록 안에서 로고 · 정보 · 동작 버튼 자리를 새로 잡았다. 동작 버튼은 화면 아래쪽 띠로 내렸다.

폰에서 정리한 구조는 데스크톱에도 거꾸로 반영했다. 마지막엔 폰 여백을 한 값으로 통일하고 배포했다.

@media (max-width: 40rem) { 폰 배치 }

사잇값

데스크톱과 폰 사이, 그리고 둘 다에 안 맞는 화면을 하나씩 잡았다.

태블릿데스크톱 배치가 좁아 보이는 너비부터 태블릿 배치로 넘겼다. 처음 정한 폭도 답답해서 같은 날 기준을 더 넓혔다.

낮은 화면폭이 같아도 높이가 낮으면 오른쪽 조절판이 천을 덮고, 세로 막대를 둘 자리도 모자랐다. 높이 조건을 붙여 낮은 화면에서만 조절판을 가로로 눕혔다. 기준은 기기 전체 높이가 아니라 사파리에서 실제로 보이는 높이로 잡았다.

가로 폰가로로 돌린 폰은 너비만 보면 데스크톱과 같다. 가로 방향 · 낮은 높이 · 터치 기기, 세 조건을 함께 걸어 따로 잡았다. 시안 셋을 띄워 보고 그중 하나로 정했다. 위 가로 화면은 폰으로 볼 때만 가로 폰 배치로 보인다.

경계에서 크기가 갑자기 튀지 않도록, 크기는 min() 같은 식으로 계산하고 미디어쿼리는 배치만 바꾸게 했다.

@media (max-width: 75rem) { 태블릿 }
@media (max-width: 40rem) and (max-height: 52rem) { 낮은 폰 }
@media (orientation: landscape) and (max-height: 30rem)
   and (pointer: coarse) { 가로 폰 }

다시 짜며 줄이기

다시 짜기 직전, CSS에는 @media 블록이 17개 있었다. 배치 갈래만 해도 데스크톱 · 태블릿 · 낮은 태블릿 · 폰 · 낮은 폰 · 가로 폰 여섯이었다. 갈래가 겹치는 화면에서는 두 규칙이 한꺼번에 걸려 천이 잘렸고, 칸 수가 바뀌는 경계에서는 크기가 튀었다. 사잇값 쿼리 대부분은 2페이지 스크롤 · 세로 줌 막대 · 배경색 정사각형처럼 특정 요소의 자리를 맞추려고 생긴 것이었다.

그때 아트팀의 새 시안이 와서 배치를 세 단으로 처음부터 다시 짰다. 2페이지 구조 · 줌 막대 · 정사각형이 빠지자, 그 요소들을 위해 있던 사잇값 쿼리도 같이 지울 수 있었다. 블록은 17개에서 7개로 줄었다. 태블릿은 데스크톱 배치를 그대로 쓰고 눈금 간격만 바꾼다.

남은 갈래는 데스크톱 · 폰 · 가로 폰 셋으로 줄었다. 폰 조건에서 가로 폰을 뺐고, 나중에 세로로 든 아이패드를 폰 쪽에 합쳤다. 위 두 화면이 같은 아이패드를 세로 · 가로로 든 모습이다.

갈래가 줄자 한 블록에만 남은 값이 드러났다. 글자 크기를 바꿀 때 가로 폰 블록만 빠져 있었다.

입력 방식 조건도 화면 크기와는 따로 걸었다. 마우스를 올리면 낱말이 굵어지게 하고, 터치 환경에서는 낱말 둘레에 넓은 누름 영역을 뒀다.

@media (max-width: 64rem) { 눈금 간격 }
@media (max-width: 40rem) and (orientation: portrait), …,
       (max-width: 64rem) and (orientation: portrait) { 폰 }
@media (orientation: landscape) and (max-height: 30rem)
   and (pointer: coarse) { 가로 폰 }
@media (hover: hover) { 올리면 굵게 }
@media (pointer: coarse) { 넓은 누름 영역 }

다음에 한다면

  • 갈래부터 정한다이번엔 갈래를 늘렸다가 마지막에 데스크톱 · 폰 · 가로 폰 셋으로 줄였다. 처음부터 이 셋으로 시작하고, 태블릿은 데스크톱을, 세로 태블릿은 폰을 따르게 한다.
  • 확인할 화면을 먼저 정한다낮은 폰 · 가로 폰 · 세로 태블릿은 폰 작업 도중이나 끝난 뒤에 하나씩 발견했다. 넓은 화면, 폰, 낮은 폰, 가로 폰, 세로 · 가로 태블릿을 처음부터 목록에 넣고 같이 본다. 높이는 사파리에서 실제로 보이는 높이로 잰다.
  • 데스크톱과 폰 구조를 같이 짠다이번엔 폰에서 정한 구조를 나중에 데스크톱에 거꾸로 입혔다. 두 화면을 나란히 두고 구조를 한 번에 정한다.
  • 크기는 처음부터 식으로 쓴다칸 수로 정한 크기는 경계에서 튀어서 식으로 옮겼다. 처음부터 min() 같은 식으로 크기를 정하고, 쿼리는 배치만 바꾼다.
  • 폰 조건은 한 문자열로 둔다CSS와 JS가 같은 조건을 쓰게 되면서 문자열 하나를 같이 쓰게 했다. 처음부터 한 곳에 두고, 바꿀 땐 그 문자열이 쓰인 곳을 모두 같이 고친다.
  • 값을 바꿀 땐 모든 갈래를 같이 본다글자 크기를 바꿀 때 가로 폰 블록 하나가 빠졌다. 속성 하나를 고치면 모든 @media 블록에서 같은 속성을 찾는다.
